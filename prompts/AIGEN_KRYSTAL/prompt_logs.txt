INTERACTION #4: Hyperparameter Tuning Strategy for the LSTM
Date: November 19, 2026
Task: Implement a search over hidden dimension, learning rate, and batch size
      for the best-performing recurrent architecture (LSTM)
================================================================================
CONTEXT PROVIDED TO AI:
- Search space: hidden_dims = [64, 128, 256], learning_rates = [0.001,
  0.0005], batch_sizes = [32, 64] (12 combinations)
- Models are custom PyTorch with a shared training loop that includes early
  stopping and best-state restoration
- Constraint: training on CPU-only hardware (no CUDA), so the search must
  bound total wall-clock cost
- Requirement: log every run's metrics and select the configuration for a
  final full training
PROMPT USED:
"What is the best way to implement GridSearch for my PyTorch models? Should
I use Scikit-learn's GridSearchCV or a manual approach?"
AI OUTPUT SUMMARY:
- Recommended a manual nested-loop search inside the notebook
- Explained that wrapping custom PyTorch models with early stopping in
  sklearn's GridSearchCV requires fragile estimator wrappers that are prone
  to shape and state bugs
- Suggested evaluating each combination and tracking the metric of interest
MANUAL ADJUSTMENTS MADE:
1. Implementation Strategy: I agreed with the manual approach (itertools.product
   over the three hyperparameter axes inside 03_dense_rnn_lstm.ipynb) but
   refined it by creating a dedicated log_hyperparameter_run() function in
   src/train.py that appends every (params + metrics) row to a persistent
   CSV file, instead of the AI's in-memory-only suggestion. This gives an
   auditable experiment trail.
2. Metric Selection: Instead of the accuracy-only ranking the AI proposed, I
   configured the loop to track F1-score AND Cohen's kappa, sorting by F1 —
   a better balance for sentiment classification since both classes have
   equal support in the test split.
3. Cost Control: I limited each tuning run to 10 epochs with patience=3,
   then retrained the winner (hidden_dim=64, lr=0.001, batch_size=32,
   best F1 = 0.6923) with the full 20-epoch budget.
4. Critical Analysis of an Unstable Result: the final retraining collapsed to
   Accuracy 0.525 / Kappa 0.05 despite the best search score. Rather than
   hiding it, I diagnosed it as a consequence of early stopping restoring a
   weak checkpoint on this small dataset, documented the limitation honestly
   in the comparative table, and reported it as evidence that the tuned LSTM
   underperformed the DenseNN baseline on this data.
5. Visualization: I added a seaborn barplot (F1 vs hidden_dim, hue=lr) so the
   tuning landscape can be inspected visually in the report.
FINAL IMPLEMENTATION:
- Files: src/train.py (log_hyperparameter_run),
  notebooks/03_dense_rnn_lstm.ipynb (grid-search cells),
  logs/hyperparameter_search.csv, outputs/metrics/lstm_tuned_metrics.json,
  outputs/metrics/model_comparison.csv / .json
