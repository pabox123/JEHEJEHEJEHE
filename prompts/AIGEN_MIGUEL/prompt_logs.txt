INTERACTION #2: Turing Machine Connection (Theoretical Analysis)
Date: November 12, 2026
Task: Connect RNN/LSTM/Transformer architectures to Turing Machine concepts
================================================================================

CONTEXT PROVIDED TO AI:
- Course: Computacion y Estructuras Discretas III (CED-III)
- Learning Objectives: OE3.3 to OE3.6 (Turing Machines, computability, formal
  languages)
- Key concepts to cover: memory, sequence processing, computability
- Audience: academic report for a university-level computer science course

PROMPT USED:
"Explain the relationship between LSTM memory, Transformer attention mechanisms,
and Turing Machines for an academic report. Focus on how these architectures
process sequences and manage memory, and relate this to computability theory."

AI OUTPUT SUMMARY:
- Superficial analogy: "Both process information step-by-step like a Turing
  Machine tape"
- Implied that Transformers process sequentially (incorrect)
- Did not distinguish hidden-state memory from attention-based access
- No discussion of computability limits or formal language classes

MANUAL ADJUSTMENTS MADE:
1. Corrected the central misconception: a Transformer does not carry a single
   recurrent hidden state across positions. Self-attention gives every position
   direct access to the whole context window in parallel during training.
2. Refined the recurrent analogy: h_t is the closest analog to the TM
   "state + working memory", because it compresses the processed prefix into a
   fixed-size vector; the recurrent update plays the role of a transition rule.
   The LSTM cell state adds explicit write/erase/expose operations via gates.
3. Separated complexity from computability:
   - RNN/LSTM: O(n) sequential steps; gradients vanish over long spans.
   - Self-attention: O(n^2) pairwise operations, but O(1) sequential depth.
   These are complexity statements, not computability statements.
4. Bounded the computability claim (OE3.6): with finite precision, a fixed
   hidden dimension and a 64-token window, the deployed models are bounded
   devices, not unrestricted Turing Machines. Turing-completeness results for
   Transformers hold only under idealized assumptions (unbounded precision,
   unbounded context).
5. Replaced the incorrect citation (see correction C3 above) with Yun et al.
   (2020), Perez et al. (2021) and Hahn (2020).

FINAL IMPLEMENTATION:
- File: docs/report.md (Section 5: Relation to Turing Machine Concepts)
- Explicitly framed as an architectural interpretation, not an experimental
  result obtained from this repository.

INTERACTION #4: Training Loop Optimization on CPU
Date: November 14, 2026
Task: Reduce fine-tuning time in a CPU-only environment
================================================================================

CONTEXT PROVIDED TO AI:
- Hardware: Asus laptop, Windows, CPU only (no CUDA device)
- Model: DistilBERT fine-tuning on ~1,000 samples
- Symptom: epochs far slower than expected for a dataset of this size

PROMPT USED:
"My Transformer training loop is slow on CPU for a dataset of 1,000 samples.
How can I optimize it without losing accuracy?"

AI OUTPUT SUMMARY:
- Recommended using a GPU (not available on this machine)
- Recommended reducing the batch size (increases the number of optimizer steps)
- Recommended gradient accumulation (addresses memory, not throughput)
- Did not identify repeated tokenization as the bottleneck

MANUAL ADJUSTMENTS MADE:
1. Diagnosed the hot path: tokenization was executed inside __getitem__, i.e.
   once per sample per epoch, instead of once per dataset.
2. Rejected the GPU suggestion (no CUDA device) and the smaller-batch suggestion
   (it worsens throughput when the loop is CPU-bound).
3. Moved tokenization out of the per-item path and kept num_workers=0, since
   worker startup costs exceed the benefit for a small in-memory dataset.
4. Withheld the numeric speedup claim until timed runs are written to
   logs/experiment_notes.md (see correction C4).

FINAL IMPLEMENTATION:
- File: notebooks/04_transformer_extension.ipynb (cells 7-8)
